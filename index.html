01 MEMORY · 記憶體配置

程式的記憶體佈局

典型 C 程式執行時，記憶體分成 text、data、bss、heap、stack 與 system 六大區段。理解「變數被放在哪」是面試的高頻送分題。

區段存放內容典型例子特性
text可執行 CPU 指令函式本體唯讀、可共用
data已初始化靜態變數int g = 5; 全域分唯讀 / 可讀寫
bss未初始化靜態變數static int c;啟動前歸零
heap動態配置malloc / new向高位址成長
stack區域變數、呼叫狀態函式內 int x;向低位址成長
system命令列參數、環境變數argv / env與系統相關

Q Little-Endian vs Big-Endian

同一個多位元組數值在記憶體中的位元組排列順序不同。Little-endian 把最低位元組放在最低位址（x86 / ARM 常見）；Big-endian 反之（網路位元組序）。

02 KEYWORDS · 關鍵字與限定詞

extern · static · const · volatile

儲存類別與型別限定詞是 C 語言觀念題的核心。重點不在背定義，而在「編譯器看到它時行為會怎麼改變」。

extern 宣告變數定義在他處

extern 告訴編譯器某個變數的定義在別的位置（同檔或他檔）。它只是「宣告」，不配置空間。若在 extern 同時給初值會被當成「定義」，造成重複定義錯誤。

extern.c
// some.c
double some_var = 1000;

// main.c — 正確用法：先宣告、再使用
extern double some_var;   // 只宣告，編譯器去他處找定義
some_var = 100;            // OK

extern double some_var = 100; // ✗ error: 同時有 extern 與初值

static 延長壽命 · 限縮可見範圍

  • 區域 static 變數：函式結束後仍存活於記憶體，直到程式結束；但外部仍無法存取。
  • 全域 static 變數 / 函式：可見範圍僅限於該原始檔，可避免命名衝突。
static_counter.c
void count(void) {
    static int c = 1;   // 只初始化一次，跨呼叫保留值
    printf("%d\n", c);
    c++;
}
// 呼叫 10 次 → 印出 1,2,3,…,10

volatile 禁止最佳化、每次都讀實體記憶體

被 volatile 修飾的變數可能被「非預期地」更新，因此編譯器不對它做最佳化，每次存取都從記憶體實體位址讀最新值，而非快取在暫存器。嵌入式系統處理 I/O、中斷、RTOS 時尤其重要。

  • 修飾 ISR（中斷處理）中可能被改的全域變數
  • 修飾多執行緒共用的全域變數
  • 設備硬體暫存器（如狀態暫存器）
面試陷阱 int SQR(volatile int *a){ return (*a)*(*a); } 有 bug —— *a 被讀兩次，volatile 下兩次值可能不同，結果未必是平方。正解：先讀進區域變數 int b = *a; return b*b;

Q const 與 volatile 可以合用嗎？

extern const volatile unsigned int rt_clock; —— RTOS 中常見。rt_clock 被時鐘中斷更新（所以 volatile，要每次重讀），但程式其他地方不應修改它（所以 const）。兩者並不矛盾。

Q 解釋 lvalue 與 rvalue

答案 lvalue（location value）是「運算式結束後仍保留狀態的物件」 —— 也就是有名字、有記憶體位址、可放在等號左邊的東西。所有變數（含 const 變數）都是 lvalue。

rvalue（read value）是「運算式求值後就不保留的暫存值」 —— 沒有名字、不可被取址，通常出現在等號右邊。

區別範例：++c 是 lvalue（回傳變數本身）；c++ 是 rvalue（回傳遞增前的暫存副本）。所以 ++c = 5 合法，c++ = 5 不合法。

Q 解釋 #error

#error 是前置處理指令，編譯期遇到它會立即中止編譯並印出後面的訊息。常用於條件編譯檢查環境是否合法。

error_directive.c
#if !defined(__STDC__)
#error "需要 ANSI C 編譯器才能編譯本檔"
#endif

Q 指標宣告 Ival = *p; 可能的錯誤

deref_err.c
int  ival;
int **p;
ival = *p;   // ✗ *p 的型別是 int*（指標），不能指派給 int
答案 p 是「指向指標的指標」，*p 解一層後型別為 int*，要再解一層 **p 才是 int。直接把指標指派給整數會型別不符；且 p 未初始化就解參考是未定義行為。
03 POINTER · 指標與宣告判讀

複雜宣告的「右左法則」

面試最愛考的就是讀懂一串 int (*p[10])(int) 到底是什麼。從識別字開始，先右後左、遇括號優先，逐層往外讀。

宣告含意
int p;一個整數
int *p;指向整數的指標
int **p;指向「整數指標」的指標
int p[10];10 個整數的陣列
int *p[10];10 個「整數指標」的陣列
int (*p)[10];指向「10 個整數陣列」的指標
int (*p)(int);指向函式的指標（吃 int、回傳 int）
int (*p[10])(int);10 個函式指標的陣列
關鍵差異 int *ptr[10] 是「指標的陣列」（陣列在外）；
int (*ptr)[10] 是「指向陣列的指標」（括號讓 ptr 先是指標）。

Q const 修飾的位置決定誰不可變

const_ptr.c
const int *foo;        // 指向 const int：內容不可改，指標可改
int const *foo;        // 同上（const 與 int 可互換位置）
int * const foo;       // const 指標：指標不可改，內容可改
int const * const foo; // 指標與內容都不可改

口訣：const 在 * 左邊 → 鎖「內容」；const 在 * 右邊 → 鎖「指標」。

Q 函式指標：把函式當成變數傳遞

函式名稱本身就是指向該函式記憶體位址的參考。可宣告 int (*op)(int,int) 並讓它在 add / mult 間切換。

func_ptr.c
int add(int a,int b){ return a+b; }
int mult(int a,int b){ return a*b; }

int main(){
    int (*op)(int,int);
    op = add;  printf("%d\n", op(3,5)); // 8
    op = mult; printf("%d\n", op(3,5)); // 15
}

Q 經典輸出題：a+1 vs &a+1

ptr_arith.c
int a[5] = {1,2,3,4,5};
int *p = (int*)(&a + 1);
// *(a+1)  = a[1] = 2
// *(p-1)  = a[4] = 5
為什麼 a+1 的型別是 int*，加 1 跳一個 int（4 bytes）→ 指向 a[1]。
&a+1 的型別是 int(*)[5]，加 1 跳「整個陣列」（20 bytes）→ 指向陣列尾端之後；p-1 回到 a[4]。

Q 後置 / 前置遞增的指標副作用

inc.c
int a[5] = {1,2,3,4,5};
int *p = a;
*(p++) += 123;   // 改 a[0]，p 移到 a[1]
*(++p) += 123;   // p 先移到 a[2]，改 a[2]
// 結果：{124, 2, 126, 4, 5}
變化題 若是 *(p++) += 100; *(++p) += 97; → 結果為 {101, 2, 100, 4, 5}。萬年面試題，務必手算 trace 過一遍。

Q 用 a[ ] 取值的小技巧

offset.c
int a[10] = {1,2,…,10};
int *p = &(a + 1)[3]; // 等同 a[1+3] = a[4]
printf("%d\n", *p);      // 輸出 5
04 MACRO · 巨集與前置處理

#define 的陷阱與技巧

巨集在前置處理階段做純文字替換，不做型別檢查也沒有運算優先序概念 —— 這正是它最容易出錯之處。括號是你的好朋友。

Q 為什麼 #define SUM(a,b) a+b 會出包？

若呼叫 SUM(2,5)*10，文字展開成 2 + 5 * 10，因為先乘後加 → 答案是 52 而非預期的 70。正確寫法要把整體與每個參數都包上括號。

macro_pitfalls.c
#define SUM(a,b)   ((a)+(b))           // 正確：全包括號
#define MAX(x,y)   ((x)>=(y)?(x):(y))   // 求最大值
#define MIN(x,y)   ((x)<=(y)?(x):(y))   // 求最小值
#define SQUARE(x)  ((x)*(x))            // 平方
#define SECONDS_PER_YEAR (60*60*24*365)UL // 一年秒數，UL 防溢位

Q 字串化運算子 #

要寫一個巨集 FUN(X) 印出 X 的 ASCII code：用 # 把參數轉成字串，再取第一個字元。

stringize.c
#define FUN(X) (#X[0])
printf("%d \n", FUN(a)); // 印出 'a' 的 ASCII = 97
macro 的隱藏 bug #define ADD_TWO(x,y) x+=2;y+=2; 配上 if(flag) ADD_TWO(j,k); 展開後，只有 j+=2; 受 if 控制，k+=2; 永遠執行 —— 這是多語句巨集未用 do{…}while(0) 包起來的經典災難。

inline vs #define

inline 也像巨集般展開以加速，但更安全：

  • 參數只計算一次，避免巨集重複求值的錯誤
  • 參數型別會被檢查並做必要轉換
  • 編譯器不一定真的展開 —— inline 僅是「建議」

05 BITWISE · 位元運算

用位元思考

韌體面試的命脈。乘除取餘改成位移與遮罩、不用暫存變數交換、判斷 2 的冪次 —— 這些都是必背招式。

Q 用位元運算取代算術

需求位元寫法原理
N % 4N & 3取低 2 位
N / 16N >> 4右移 4 位
N * 2N << 1左移 1 位

Q set / clear / inverse 指定位元

bit_ops.c
#define SET_BIT(x,n)     ((x) |=  (1 << (n)))  // 設為 1
#define CLEAR_BIT(x,n)   ((x) &= ~(1 << (n)))  // 設為 0（遮罩後 AND）
#define INVERSE_BIT(x,n) ((x) ^=  (1 << (n)))  // 反轉

Q 不用第三變數交換兩數（XOR swap）

xor_swap.c
void xorSwap(int *x, int *y){
    if (x != y){      // 防同位址自我清零
        *x ^= *y;
        *y ^= *x;
        *x ^= *y;
    }
}
小心 若 x == y（同一位址），XOR swap 會把該值清成 0，務必先判斷。

Q 一行判斷是否為 2 的冪次

power_of_two.c
bool isPowerOfTwo(int n){
    return n > 0 && (n & (n-1)) == 0;
}
// 2的冪次只有一個 bit 為 1，n&(n-1) 會清掉它變 0

Q 布林代數化簡：v 的值？

bool_algebra.c
unsigned long v1 = 0x00001111;
unsigned long v2 = 0x00001202;
v = (v1 & ~v2) | v2;
// = (v1|v2) & (~v2|v2) = (v1|v2) & 1 = v1 | v2
// = 0x00001313

Q 不用除法 / 取餘判斷是否為 3 的倍數

multiple_of_3.c
int divide3(int a){
    int ans = 0;
    while(a){
        ans += a & 1; a >>= 1; // 奇數位
        ans -= a & 1; a >>= 1; // 偶數位（相減）
    }
    return !ans;  // 奇偶位元和之差為 0 → 3 的倍數
}

Q 求最高位元在第幾位（瑞昱題）

int a = 0xfafc; 求第 9 個 bit 值：return (a >> 8) & 1; —— 右移 8 位後 AND 1 取出該位。0xfafc = 1111101011111100，第 9 位為 0。

Q 連續位元運算後 A 的值

char A = 31;（二進位 0001 1111），逐步運算：

運算結果說明
A = A | 14;310001 1111 | 0000 1110 = 0001 1111，14 的位元已包含於 31
A = A & (~A);0任何數 AND 自己的補數恆為 0
A = A ^ A;0任何數 XOR 自己恆為 0

Q 將某數的第 x 個 bit 改成 1 或 0（群聯題）

答案 改成 1：直接 OR 一個遮罩 → x |= (1 << n);
改成 0：先做反遮罩再 AND → x &= ~(1 << n);

Q 跨變數複製指定位元

把來源的某幾個 bit 複製到目標的某幾個 bit：先用遮罩清掉目標位元，再把對齊後的來源位元 OR 進去。

copy_bits.c
// 取 src 的第 4~7 位，覆蓋到 dst 的第 1~4 位
unsigned field = (src >> 4) & 0xF;   // 取出 4 個 bit
dst &= ~(0xF << 1);                  // 清掉目標位元
dst |= (field << 1);                 // 對齊後寫入
06 ALGORITHMS · 程式與演算法

上機常見題型

字串處理、排序、Linked List 與經典 DP 題。多數可在白板手寫，重點是邊界條件與時間 / 空間複雜度的權衡。

字串 原地反轉字串

reverse_string.c
char* reverseString(char* s){
    size_t len = strlen(s);
    for(int i = 0; i < len/2; i++){
        char t = s[i];
        s[i] = s[len-1-i];
        s[len-1-i] = t;
    }
    return s;
}

DP 最大連續子陣列和（Kadane）

給 [-2,1,-3,4,-1,2,1,-5,4]，最大子陣列 [4,-1,2,1] 和為 6。經典 O(n) 解法：累加為負就重置。

max_subarray.c
int maxSubArray(int* nums, int n){
    int max = nums[0], local = nums[0];
    for(int i = 1; i < n; i++){
        local = (local > 0) ? local + nums[i] : nums[i];
        max   = (max < local) ? local : max;
    }
    return max;
}

List 反轉單向 Linked List（迭代）

reverse_list.c
struct ListNode* reverseList(struct ListNode* head){
    struct ListNode *prev = NULL, *cur = head, *next;
    while(cur){
        next = cur->next;   // 暫存下一個
        cur->next = prev;   // 反指
        prev = cur;         // 推進
        cur  = next;
    }
    return prev;            // 新的 head
}

List 不知長度找中點（快慢指標）

middle_node.c
Node *slow = head, *fast = head;
while(fast && fast->next){
    fast = fast->next->next;  // 走兩步
    slow = slow->next;        // 走一步
}
// fast 到底時，slow 正好在中間

Q 印出 N 大小的菱形 / 三角形

白板常見圖形題：外層控制行，內層先印空白再印 *。菱形分上下兩個三角形處理。掌握「第 i 行有 2i-1 個星號、前面 n-i 個空白」即可。

triangle.c
for(int i = 0; i < n; i++){
    for(int j = 0; j < n-i-1; j++) printf(" ");
    for(int k = 0; k < 2*(i+1)-1; k++) printf("*");
    printf("\n");
}

字串 偵測大小寫用法（Detect Capital）

判斷單字是否符合：全大寫（USA）、全小寫（leet）、或僅首字母大寫（Google）。其餘如 FlaG 回傳 false。

detect_capital.c
bool detectCapitalUse(char* w){
    int n = strlen(w), upper = 0;
    for(int i = 0; i < n; i++)
        if(w[i] >= 'A' && w[i] <= 'Z') upper++;
    // 全大寫 || 全小寫 || (只有首字大寫)
    return upper == n || upper == 0 ||
           (upper == 1 && w[0] >= 'A' && w[0] <= 'Z');
}

排序 合併兩個已排序陣列（Merge Sorted Array）

把 nums2 接到 nums1 後再整體排序。nums1=[1,2,3,0,0,0]、nums2=[2,5,6] → [1,2,2,3,5,6]。

merge_sorted.c
void merge(int* a, int m, int* b, int n){
    for(int i = 0; i < n; i++) a[m+i] = b[i];  // 先接上
    for(int i = 0; i < m+n-1; i++)            // 再 bubble sort
        for(int j = 0; j < m+n-1-i; j++)
            if(a[j] > a[j+1]){ int t=a[j]; a[j]=a[j+1]; a[j+1]=t; }
}

排序 奇數遞增在前、偶數遞減在後

給正整數數列，重排成：奇數部分由小到大、偶數部分由大到小。做法 —— 分流到兩個陣列，奇數陣列升冪、偶數陣列降冪，再串接。

解題步驟 1. 用 array[i] & 1 判斷奇偶並分流到 odd[] / even[]。
2. odd[] 升冪排序、even[] 降冪排序（bubble sort 即可）。
3. 先放奇數、再放偶數，合併成結果陣列。

DP 長度 K 的最大區段和變形（連續和最大）

輸入 [2,3,-8,1,2,3]，求連續子陣列最大和 → 6（第 4~6 項）。與 Kadane 同源，累加為負就重置。

max_window.c
int max = 0, temp = 0;
for(int i = 0; i < len; i++){
    temp = (temp >= 0) ? temp + a[i] : a[i];
    if(temp > max) max = temp;
}

陣列 兩陣列交集（Intersection）

nums1=[4,9,5]、nums2=[9,4,9,8,4] → 交集 [9,4]（去重）。雙層迴圈比對，命中後檢查結果是否已存在再加入。

intersection.c
for(int i = 0; i < n1; i++)
  for(int j = 0; j < n2; j++)
    if(nums1[i] == nums2[j]){
        int k = 0;
        while(k < *sz && res[k] != nums1[i]) k++;
        if(k == *sz) res[(*sz)++] = nums1[i];  // 不重複才加
        break;
    }

質數 計算小於 n 的質數個數

輸入 10 → 輸出 4（2,3,5,7）。逐一檢查每個數是否為質數並計數。

count_primes.c
bool isPrime(int n){
    if(n < 2) return false;
    for(int j = 2; j*j <= n; j++)   // 只需檢查到 √n
        if(n % j == 0) return false;
    return true;
}
// 第 n 個質數：從 2 開始計數，第 n 個 isPrime 為真者即是

質數 判斷兩數是否互質（coprime）

互質 = 最大公因數為 1。最簡潔做法是輾轉相除法求 GCD。

coprime.c
int gcd(int a, int b){ return b ? gcd(b, a % b) : a; }
// gcd(a,b) == 1 → 互質（coprime），否則 not coprime

陣列 找出第二大的值

一次掃描維護最大值 max1 與次大值 max2，O(n) 不需排序。

second_max.c
int m1 = INT_MIN, m2 = INT_MIN;
for(int i = 0; i < n; i++){
    if(a[i] > m1){ m2 = m1; m1 = a[i]; }
    else if(a[i] > m2 && a[i] != m1) m2 = a[i];
}
// m2 即為第二大值

陣列 找出被抽掉的數（不知位置）

原陣列為 0~n 連續或已知總和。把「應有的總和」減去「現有總和」，差值即缺失的數。O(n) 時間、O(1) 空間。

missing_num.c
int full = n * (n + 1) / 2;  // 0..n 的應有總和
int sum = 0;
for(int i = 0; i < n; i++) sum += a[i];
// 缺失值 = full - sum

字串 自幹 strcmp

逐字元比較，回傳差值：相等回 0，前者大回正、後者大回負。

my_strcmp.c
int myStrcmp(const char* a, const char* b){
    while(*a && (*a == *b)){ a++; b++; }
    return *(const unsigned char*)a - *(const unsigned char*)b;
}

數列 廣義費氏數列：給位置 n 求值

數列 11,12,23,35,58…（每項為前兩項之和，起始 a=11, b=12）。迭代法 O(n)。

fib_like.c
int a = 11, b = 12;
if(n == 0) return a;
if(n == 1) return b;
for(int i = 2; i <= n; i++){ int t = b; b = a + b; a = t; }
return b;

Q call by value vs call by reference 的 SWAP

call by value 傳的是副本，函式內交換不影響外部 → 主程式印出的值不變。call by reference（傳指標）才能真正交換。

swap_ref.c
// call by value：無效，外部 a,b 不變
void swapVal(int a, int b){ int t=a; a=b; b=t; }

// call by reference：有效
void swapRef(int *a, int *b){ int t=*a; *a=*b; *b=t; }

C++ 運算子多載（operator +）

實作一個含 4 個整數的向量類別，多載 + 讓兩個物件可直接相加。

my_vector.cpp
class MyVector {
    int e[4];
public:
    MyVector(int a=0,int b=0,int c=0,int d=0){ e[0]=a;e[1]=b;e[2]=c;e[3]=d; }
    MyVector operator+(const MyVector& o) const {
        return MyVector(e[0]+o.e[0], e[1]+o.e[1],
                        e[2]+o.e[2], e[3]+o.e[3]);
    }
};

Q 子集合最大和

給陣列，求所有子集合中總和的最大值。[2,-1,4,-2,2] → 6（子集合 [2,4,2] 或題述 [2,4]）。關鍵洞察：只要把所有正數加起來就是最大子集合和（負數不選）。

subset_max.c
int sum = 0;
for(int i = 0; i < n; i++)
    if(a[i] > 0) sum += a[i];   // 只挑正數，O(n)
// 全為負時，最大子集合和取最大的單一元素

Q 印出 0~500 但每次隨機抽一個、不重複（群聯白板題）

建一個 0~500 的陣列，用 Fisher–Yates 洗牌：每次從未抽過的範圍隨機取一個與末端交換，再縮小範圍。保證 O(1) 抽取且不重複。

shuffle_pick.c
int pool[501];
for(int i = 0; i <= 500; i++) pool[i] = i;
for(int last = 500; last >= 0; last--){
    int r = rand() % (last + 1);
    int t = pool[r]; pool[r] = pool[last]; pool[last] = t;
    printf("%d ", pool[last]);  // 抽出且不再重複
}

Q 寫一個會發生 memory leak 的程式

leak.c
void leak(){
    int *p = malloc(100 * sizeof(int));
    p = NULL;   // ✗ 指標被覆蓋，那塊記憶體再也 free 不到 → leak
}                  // 正解應在覆蓋前 free(p);

dangling.c
int* bad(){

07 ARCHITECTURE · 計算機結構

CPU、快取與管線

韌體與系統職缺的硬核題庫。重點在「資料如何在記憶體階層間流動」、「管線如何被打斷」，以及 CPU 與 GPU 在設計哲學上的根本差異。

Q CPU vs GPU 的設計差異

兩者都是處理器，但最佳化的目標完全相反：CPU 為「低延遲、複雜控制流」設計，GPU 為「高吞吐、大量平行」設計。

面向CPUGPU
核心數少（數個~數十個）、強多（數千個）、弱
最佳化目標單執行緒延遲（latency）整體吞吐量（throughput）
控制單元複雜：分支預測、亂序執行精簡：多核共用控制
快取比例大（佔晶片面積高）小，靠大量執行緒藏延遲
適合工作分支多、序列相依的任務SIMD 式大量同質運算（矩陣、繪圖、ML）
一句話 CPU 像幾位博士，能處理複雜決策；GPU 像幾千個小學生，適合同時做大量簡單算術。深度學習訓練吃 GPU，正是因為它本質是大量平行的矩陣乘法。

Q 記憶體階層（Memory Hierarchy）

越靠近 CPU 越快但越貴、越小。設計原則是讓「最常用的資料」待在最快的層級。

Q 區域性原理（Locality）

快取之所以有效，靠的是程式存取的兩種規律：

  • 時間區域性（Temporal）：最近用過的資料很可能再被用（如迴圈變數）→ 留在快取裡。
  • 空間區域性（Spatial）：用到某位址，附近位址也很可能被用（如陣列循序存取）→ 以 cache line 為單位整批載入。
實戰影響 二維陣列「列優先」逐列走訪（row-major）比「行優先」快很多，因為前者符合空間區域性、cache line 命中率高。這是 C 語言效能題的經典。

Q 快取命中 / 未命中與映射方式

映射方式特性權衡
直接映射
(Direct-mapped)		每個記憶體區塊只能放固定一格查找最快、硬體簡單；衝突率高
全關聯
(Fully associative)		區塊可放任意格命中率最高；比對成本昂貴
N 路組關聯
(N-way set assoc.)		折衷：每組 N 格可放實務主流（如 8-way）

三種未命中（3C）：Compulsory（首次冷啟動）、Capacity（容量不夠）、Conflict（映射衝突）。

Q 指令管線（Pipeline）與 Hazard

經典 5 級 RISC 管線：取指（IF）→ 解碼（ID）→ 執行（EX）→ 存取記憶體（MEM）→ 寫回（WB）。多條指令重疊執行以提升吞吐，但會遇到三種冒險：

  • 結構冒險（Structural）：硬體資源衝突（兩指令同時要用同一單元）→ 增加資源或暫停。
  • 資料冒險（Data）：後指令需要前指令還沒寫回的結果 → 用前饋 / 旁路（forwarding）把結果直接送過去，或插入 stall。
  • 控制冒險（Control）：分支結果未定，不知下一條取哪 → 靠分支預測（branch prediction），預測錯就清空管線（flush）。

Q RISC vs CISC

RISC（如 ARM、RISC-V）CISC（如 x86）
指令集精簡、定長、單純龐大、變長、複雜
每條指令多為單 cycle可能多 cycle、含微碼
暫存器多相對少
取捨編譯器負擔重、易管線化、省電程式碼密度高、相容包袱重

Q 快取一致性（Cache Coherence）

多核心各有私有快取時，同一份資料可能存在多份副本。需要協定確保大家看到一致的值，最常見是 MESI —— 每條 cache line 標記為四種狀態之一：

  • Modified：本核已改、與主記憶體不同，且是唯一副本
  • Exclusive：只有本核有、且與主記憶體相同
  • Shared：多核共有、皆與主記憶體相同
  • Invalid：此副本失效，需重新載入
關聯 volatile 這也呼應前面的 volatile：硬體有一致性協定，但編譯器層級的暫存器快取要靠 volatile 處理。兩者解決的是不同層級的「看到舊值」問題。
08 OPERATING SYSTEM · 作業系統

行程、排程與記憶體管理

行程 vs 執行緒、同步機制、虛擬記憶體與死結 —— 這四大主題幾乎是每場系統面試的必考核心。重點在理解「為什麼需要」而非死背定義。

Q Process vs Thread

面向行程 Process執行緒 Thread
記憶體空間各自獨立（隔離）共用所屬行程的位址空間
建立成本高低
溝通方式IPC（pipe、shared memory、socket…）直接讀寫共用變數（需同步）
當機影響互不影響一個崩潰可能拖垮整個行程
切換開銷大（換頁表、flush TLB）小（共用大部分資源）
一句話 行程是「資源分配」的單位，執行緒是「CPU 排程」的單位。同一行程的多個執行緒共用程式碼、資料與 heap，但各自擁有獨立的 stack 與暫存器 / PC。

Q 行程狀態與 context switch

行程在生命週期中於幾個狀態間轉換，作業系統靠 context switch（儲存舊行程的 PC、暫存器等到 PCB，載入新行程的狀態）來切換 CPU。

Q CPU 排程演算法

演算法原理特性 / 缺點
FCFS先到先服務簡單；長工作卡住短工作（convoy effect）
SJF最短工作優先平均等待最短；需預知執行時間、可能餓死長工作
Round Robin時間片輪轉公平、回應快；time quantum 太小則切換開銷大
Priority依優先權低優先權可能餓死 → 用 aging 補償
MLFQ多層回饋佇列動態調整，兼顧互動性與吞吐

搶占（preemptive）：排程器可強制中斷正在執行的行程（如 RR、搶占式 Priority）；非搶占：行程主動讓出 CPU 才切換（如 FCFS、SJF）。

Q 同步機制：Mutex / Semaphore / Spinlock

機制用途等待時行為
Mutex互斥鎖，保護臨界區（一次一人）睡眠（讓出 CPU）；有擁有者概念
Semaphore計數號誌，控制 N 個資源 / 同步順序睡眠；可 >1（counting）或 =1（binary）
Spinlock短臨界區、不可睡眠情境（如 ISR）忙等（busy-wait）空轉
選用準則 臨界區很短、且不能睡（中斷上下文）→ spinlock；臨界區長、可睡 → mutex。spinlock 在等待期間持續燒 CPU，用錯場合反而更慢。

Q 競態條件與臨界區（Race Condition）

多執行緒同時讀改同一變數、結果取決於執行時序，就是競態。經典範例 count++ 並非原子操作：

race.c
// count++ 實際拆成三步，兩執行緒交錯就會丟失更新
int tmp = count;   // 1. 讀
tmp = tmp + 1;     // 2. 加
count = tmp;       // 3. 寫回
// 解法：用 mutex 鎖住，或用原子操作 atomic_fetch_add

Q 死結（Deadlock）四個必要條件

四個條件同時成立才會發生死結；破壞任一個即可預防。

  1. 互斥（Mutual Exclusion） —— 資源一次只能一人持有
  2. 持有並等待（Hold and Wait） —— 持有資源的同時又等待別的
  3. 不可搶占（No Preemption） —— 資源不能被強制奪走
  4. 循環等待（Circular Wait） —— 形成環狀等待鏈
處理策略 預防（破壞四條件之一，如規定資源編號順序取得以破壞循環等待）／避免（銀行家演算法）／偵測後復原／鴕鳥策略（忽略，多數 OS 的實務選擇）。

Q 虛擬記憶體與分頁（Paging）

每個行程看到的是連續的「虛擬位址空間」，由 MMU 透過頁表（page table）翻譯成實體位址。好處：行程隔離、可用空間大於實體記憶體、方便共享與保護。

  • Page fault：存取的頁不在實體記憶體 → OS 從硬碟載入（可能先換出某頁）。
  • TLB：頁表查詢的快取，命中可省去走訪頁表的開銷。
  • Thrashing：實體記憶體不足，行程不斷換進換出頁面，CPU 大半時間在搬頁而非運算。

Q 頁面置換演算法

演算法換出哪一頁備註
FIFO最早進來的簡單；有 Belady 異常（頁框變多反而更糟）
LRU最久沒用的近似最佳；完整實作成本高，常用 clock 近似
OPT未來最久才用到的理論最佳、無法實作，僅作比較基準

Q 系統呼叫與中斷（Syscall / Interrupt）

系統呼叫是使用者程式主動請求 OS 服務（如讀檔），會從 user mode 切換到 kernel mode。中斷是硬體 / 計時器非同步通知 CPU，CPU 暫停當前工作、跳到中斷處理程式（ISR）。

ISR 撰寫要點 呼應前面 volatile 與 spinlock：ISR 中存取的共用變數要加 volatile，且因不可睡眠，同步需用 spinlock 而非 mutex；ISR 要短、把繁重工作丟給下半部（bottom half）。
09 NETWORK · 計算機網路

分層、TCP 與封包旅程

面試的網路題幾乎都繞著三件事：分層模型怎麼對應、TCP 如何可靠傳輸（握手 / 揮手 / 壅塞控制），以及「在瀏覽器輸入網址後發生什麼事」。理解每一層解決的問題比背名詞更重要。

Q OSI 七層 vs TCP/IP 四層

OSI 是教學用的參考模型，TCP/IP 是實際運作的協定堆疊。記法是把上三層（應用 / 表現 / 會議）合併成「應用層」。

Q TCP vs UDP

面向TCPUDP
連線連線導向（先握手）無連線
可靠性可靠：確認、重傳、排序不保證送達、不排序
流量 / 壅塞控制有無
表頭大小20+ bytes8 bytes（輕量）
速度較慢（開銷大）快、延遲低
適用網頁、檔案傳輸、Email直播、遊戲、DNS、VoIP
一句話 TCP 像掛號信 —— 確認對方收到、漏件重寄、保證順序；UDP 像明信片 —— 丟出去就算，快但不保證到。需要「即時但容忍少量遺失」時（直播、遊戲）選 UDP。

Q TCP 三次握手（Three-way Handshake）

建立連線要三步，目的是雙方都確認彼此的收 / 送能力正常，並交換初始序號（ISN）。

為什麼要三次、不能兩次？ 兩次無法讓「伺服器確認客戶端的接收能力」，且可能因網路延遲的舊 SYN 重複抵達而建立無效連線。第三次 ACK 正是用來確認雙向通道都通。

Q 四次揮手與 TIME_WAIT

關閉連線需四步，因為 TCP 是全雙工 —— 每個方向都要各自關閉。

  1. 主動方送 FIN，進入 FIN_WAIT_1
  2. 被動方回 ACK（我知道你要關了，但我可能還有資料要送）
  3. 被動方資料送完，送 FIN
  4. 主動方回 ACK，進入 TIME_WAIT（等 2×MSL 才真正關閉）
TIME_WAIT 的用意 確保最後的 ACK 確實送達（若遺失，對方會重送 FIN，本方還能補回 ACK）；並讓本次連線的舊封包在網路中全部消散，避免污染下一條用相同 port 的新連線。

Q 流量控制 vs 壅塞控制

流量控制 Flow Control壅塞控制 Congestion Control
對象接收端處理不及網路（中間路由）塞車
機制滑動視窗（rwnd，接收端通告）壅塞視窗 cwnd（傳送端推估）
目標不淹沒接收端緩衝不壓垮網路

壅塞控制四階段：慢啟動（cwnd 指數成長）→ 壅塞避免（線性成長）→ 快速重傳（收到 3 個重複 ACK 即重傳）→ 快速恢復。實際傳送窗 = min(rwnd, cwnd)。

Q 在瀏覽器輸入網址後發生什麼事？

面試萬年大題，串起所有分層。順著封包旅程講一遍：

  1. DNS 解析 —— 把網域名稱查成 IP（先查瀏覽器 / OS 快取，再問遞迴 DNS）
  2. ARP —— 在區網內由 IP 查出下一跳的 MAC 位址
  3. TCP 三次握手 —— 與伺服器（通常 port 443）建立連線
  4. TLS 握手 —— HTTPS 時協商加密金鑰、驗證憑證
  5. 送出 HTTP 請求 —— GET /，伺服器回應 HTML
  6. 瀏覽器渲染 —— 解析 HTML、再請求 CSS / JS / 圖片，繪製畫面
  7. 四次揮手 —— 傳輸結束後關閉連線（或 keep-alive 復用）

Q HTTP 方法與狀態碼

方法用途狀態碼意義
GET取得資源（安全、冪等）2xx成功（200 OK、201 Created）
POST新建 / 提交資料3xx重新導向（301 永久、302 暫時）
PUT整體更新（冪等）4xx用戶端錯誤（404 Not Found、403）
DELETE刪除資源5xx伺服器錯誤（500、502、503）
HTTP/1.1 → 2 → 3 HTTP/2 支援多工（一條連線併發多個請求，解決隊頭阻塞）；HTTP/3 改用 QUIC（基於 UDP），在傳輸層就避免 TCP 的隊頭阻塞並加快握手。

Q IP / 子網路 / NAT 基礎

  • IPv4：32 位元（如 192.168.1.1）；IPv6：128 位元，解決位址耗盡。
  • 私有位址：10.x、172.16~31.x、192.168.x 不可在公網路由。
  • NAT：家用路由器把多個私有 IP 透過一個公有 IP 對外，靠 port 對應表轉譯 —— 也是 IPv4 位址不夠用的緩解手段。
  • 子網路遮罩（CIDR）：/24 表示前 24 位是網路號，後 8 位是主機號（可容納 254 台主機）。

群聯三題（經典）

題一：給已排序 int a[20]，印出 0~500 中「不在陣列裡」的數，要求最少時間 / 空間。用單一指標掃過，匹配到就推進指標，否則印出當前值 —— O(n)、零額外空間。

phison_q1.c
void question1(int* a, int size){
    int* p = a;
    for(int i = 0; i <= 500; i++){
        if(i == *p) p++;          // 命中陣列元素，跳過
        else printf("%d ", i);
    }
}

題二：同上，但多一參數 b (0~4) 指定印出 b*100 ~ b*100+99 區間。先把指標推進到區間起點再掃。

題三：情境題 —— 在 ListArray[1000] 中找出 DataH == A && DataL == B 的節點並印出，找不到印 "no found."。沿著 NextPtr 走訪（注意：主管可能要求用雙向串列）。

phison_q3.c
#define NULL_PTR 0xFFFF
int searchList(unsigned A, unsigned B){
    unsigned e = ListHead;          // 從串列頭開始
    while(e != NULL_PTR){
        if(ListArray[e].DataH == A &&
           ListArray[e].DataL == B){
            printf("found at %u\n", e);
            return e;
        }
        e = ListArray[e].NextPtr;     // 走到下一個節點
    }
    printf("no found.\n");
    return -1;
}

11 PUZZLES · 智力 / 機智題

非程式邏輯題

面試尾聲常出現的腦力題，考的是拆解問題與清楚表達思路的能力，而非標準答案。

P1 砝碼組合 1~100 公克

用最少砝碼湊出 1~100：採二進位思維 1, 2, 4, 8, 16, 32, 64 共 7 個即可組合出 1~127 的任意整數。（這是科技業偏好的「位元」考法。）

P2 球重問題（8 顆找 1 輕球）

8 顆球，1 顆較輕，天平秤兩次找出：分成 A=[1,2,3]、B=[4,5,6]、C=[7,8]。

  1. 秤 A vs B。平衡 → 輕球在 C，再秤 7 vs 8 即知。
  2. A > B（B 輕）→ 秤 4 vs 5；平衡則 6，否則較輕者。A < B 同理在 A 中。

最少 2 次。若改成「找較重球」或「不知輕重」，用編號分組的方法同樣可解。

P3 蒙提霍爾（三杯換不換）

你選一杯後，主持人開了另一個空杯。應該換 —— 換的中獎機率是 2/3，不換只有 1/3。直覺：你初選命中大獎的機率只有 1/3，剩下 2/3 的機率集中到了主持人沒開的那杯。

P4 手扶梯綁鞋帶（瑞昱題）

從登機口走到飛機，中間有一段手扶梯，走到一半鞋帶掉了，何時綁鞋帶總時間最短？

答案：在手扶梯上綁 綁鞋帶花的時間是固定的（設為 t）。在手扶梯上綁時，雖然人站著沒走，但手扶梯仍以速度 v_扶梯 載著你前進；在平地綁則完全靜止不前進。

設總路程其餘部分時間相同，唯一差別在綁鞋帶這段 t 內的位移：扶梯上前進 v_扶梯 × t，平地前進 0。前進越多 → 剩餘要走的距離越短 → 總時間越短。故在手扶梯上綁最省時。

P5 已知 log2~log9，如何求 log7？

答案 用對數律湊近似值。例如 7² = 49 ≈ 48 = 16 × 3，所以
2·log7 ≈ log48 = log16 + log3 = 4·log2 + log3
log7 ≈ (4·log2 + log3) / 2。
或用 7³ = 343 ≈ 343、50 = 100/2 等湊法逼近，誤差極小。

P6 用正方形紙折出等邊三角形

答案（為什麼成立） 對稱性使兩道折痕等長，只需證明夾角為 60°。折疊時會構成「斜邊長為直角邊兩倍」的直角三角形 —— 這正是 30°-60°-90° 三角形，因此產生 30° 角。由此可推得前兩道折痕與紙邊各夾 15°，兩折痕之間的夾角剛好 60°，即等邊三角形。詳見下方參考連結。

P7 兩程式透過共用記憶體傳資料（瑞昱情境題）

1.1KB 記憶體，程式 A 隨機傳資料給 B，兩者無法直接溝通、每包資料 1KB。設計握手流程：

  1. 用 1KB 放資料，剩餘 0.1KB（約 100 Byte）放一個 bool 旗標。
  2. A 寫完整包資料後，將旗標設為 true。
  3. B 輪詢旗標，看到 true 就讀取資料。
  4. B 讀完把旗標設回 false，通知 A 可以寫下一包。

這是典型的單一旗標 producer–consumer 同步；嚴謹版會再加上資料是否就緒的雙旗標或環形緩衝避免競爭。
